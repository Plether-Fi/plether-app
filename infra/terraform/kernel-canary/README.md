# Isolated Sepolia Kernel canary

This Terraform root owns the new Kernel API, Alto, reconciler, image repositories, build role, and KMS keys in `plether/sepolia/kernel-canary/terraform.tfstate`. The live EntryPoint v0.8 application and Nitro RPC stacks remain in their separate states. Existing VPC, subnets, ECS cluster, API listener, Nitro ALB, database access group, and pinned task definitions are read only data sources. The root reads no SSM SecureString values. All opt-ins, task desired counts, payment modes, and the public route default to off.

Use Terraform 1.16 with `AWS_PROFILE=plether` after `aws --profile plether sts get-caller-identity` reports account `932542905614`. The AWS provider also pins `ap-southeast-1` and the account. Review a saved plan before each phase. A core Sepolia `terraform.tfvars.sepolia` file is not needed. The [Kernel qualification runbook](../../../scripts/kernel-qualification/deploy-sepolia.md) covers contract deployment and attestation.

## Phase 1: image build and sponsor signer

Set `provision_image_build_resources=true` and `provision_paymaster_key=true`. The reviewed saved plan must add only two immutable ECR repositories without expiration rules, the dedicated `plether-sepolia-kernel-canary-image-build` OIDC role/policy, and the separate secp256k1 paymaster KMS key/alias. The role trusts only the `backend-admin-sepolia` and `alto-admin-sepolia` protected GitHub environments and can push/scan only the two canary repositories. Set `KERNEL_CANARY_BUILD_ROLE_ARN` in those protected environments to the output `kernel_canary_build_role_arn`; the image workflows neither change ECS nor tag `latest`. Record their reviewed `@sha256:` image URIs and zero-CRITICAL scan evidence. The KMS signing key policy permits `ECDSA_SHA_256` signing only through the future exact canary API task role; derive the public sponsor address through KMS without exporting key material.

## Phase 1.5: dedicated SecureStrings

Set `provision_ssm_encryption_key=true` and review a plan adding only the symmetric `alias/plether-sepolia-kernel-canary-ssm` key/alias. Provision three separate SSM SecureStrings under that key: `/plether/sepolia/kernel-canary-alto-executor-private-keys`, `/plether/sepolia/kernel-canary-alto-utility-private-key`, and `/plether/sepolia/kernel-canary-aa-origin-token`. The origin token is 64 lowercase hex characters. The API execution role may decrypt only the origin parameter. The Alto execution role may decrypt only executor and utility parameters. Both are restricted to SSM service access and exact parameter encryption contexts. Use canary-specific signing keys and origin tokens. Alto receives the managed HTTPS URL through `/plether/sepolia/perps-rpc-url`, referenced by ARN so credentials stay out of Terraform state.

The key policy delegates explicit key management and recovery actions to authorized Plether IAM administrators, including `kms:PutKeyPolicy` for future repairs. Authorized IAM operators can provision and recover the three configured service parameters and the dedicated `/plether/sepolia/kernel-canary-deployer-private-key` through Singapore SSM before the ECS roles exist. Canary execution, task, and image-build roles are excluded from this operator access. Only the exact Alto and API execution roles have separate decrypt allowances for their own parameter contexts.

## Phase 2: dark service skeleton

After both image digests exist in the dedicated ECR repositories, keep `provision_image_build_resources=true`, `provision_paymaster_key=true`, and `provision_ssm_encryption_key=true` on every later plan. Set `provision_services=true`, `kernel_canary_api_image`, and `kernel_canary_alto_image` to exact account-local `@sha256:` URIs. Use the reviewed official Alto v1.2.8 ARM64 mirror. Terraform verifies both digests exist. The read-only bindings pin live API task revision `plether-sepolia:154`, Alto `plether-sepolia-alto:12`, reconciler `plether-sepolia-aa-reconciler:72`, and the reviewed Sepolia network IDs in `services_variables.tf`. Recheck those metadata bindings if any live resource is replaced.

Review that a skeleton plan adds only canary IAM roles, task definitions, security groups, internal Alto ALB/target groups, log group, and dormant ECS services. Keep `kernel_canary_alto_desired_count=0`, `kernel_canary_api_desired_count=0`, `kernel_canary_reconciler_desired_count=0`, and `kernel_canary_route_enabled=false`. The plan must not change or destroy live resources. The canary API and reconciler attach the existing narrow native-AA database client group, whose two outbound rules and RDS admission are checked by exact rule ID. The isolated state owns no RDS SG rule, so a later live core apply cannot revoke the canary database path.

Independently attest the direct-factory Kernel v4 profile `kernel-sepolia-direct-v1`, new Core paymaster and both v1.2.8 simulator deployments. Use the 14-field contract profile and the new paymaster's deployment block and hash. Fund the new paymaster's EntryPoint deposit and attest zero stake as described in the [qualification runbook](../../../scripts/kernel-qualification/deploy-sepolia.md). Before repurposing the existing isolated service names, confirm the previous deployment has drained pending ETH-paid operations, sponsorship reservations and funding claims. Retain its reconciliation bindings and deposit until those liabilities settle or expire. Apply the additive Kernel database migration before API startup, reviewing the non-concurrent funding index lock impact in a quiet window. The canary API sets `KERNEL_CANARY_API_MODE=true` and `API_BACKGROUND_WORKERS_ENABLED=false`, preventing a second live indexer or other generic database writer. Set `kernel_canary_simulators_attested`, `kernel_canary_db_schema_confirmed`, and `kernel_canary_profile_attested` after their checks. Supply both attested simulator addresses explicitly. Alto simulator auto-deployment is off.

## Private managed Alto qualification

Start only Alto with `kernel_canary_alto_desired_count=1`. The internal ALB accepts traffic from the canary API client security group. From an approved in-VPC probe using the existing canary client and egress security groups, use the Terraform output `kernel_canary_alto_internal_rpc_url`. Confirm the active task uses the approved digest, EntryPoint v0.9, both attested simulator addresses, `ALTO_SAFE_MODE=false`, `ALTO_DANGEROUS_SKIP_USER_OPERATION_VALIDATION=false` and `ALTO_EXPIRATION_CHECK=true`. Confirm the task has the managed URL reference and that its provider reports chain ID `421614`.

Check `eth_supportedEntryPoints`, a funded `eth_estimateUserOperationGas` and exact inclusion and gas debit for one signed ETH-paid direct-factory operation. Require rejection of an invalid owner signature. Keep private wallet keys on the operator machine and pass only the signed public operation to the probe. Record the image URI, task revision, deployment ID, simulator addresses, managed parameter name, gas estimate and public receipt evidence. Keep route, payment modes and reconciliation disabled during this qualification.

## API, wallet checks, and rollback

Start the API only after its profile and additive database gates. Confirm separately operated HTTPS services behind `/plether/sepolia/perps-rpc-url` and `/plether/sepolia/aa-reconciler-secondary-rpc-url` before starting the API or reconciler. Both tasks reject matching RPC hostnames at startup. Keep URL credentials out of verification logs. Alto uses the first provider and shares its quota. Keep the qualification load bounded.

For the reconciler, verify both RPCs can read the paymaster's code just before and at its deployment block. If the shared secondary RPC has pruned that state, provision a public, independently operated archive endpoint as an SSM `String` at `/plether/sepolia/kernel-canary-reconciler-archive-rpc-url`. Verify its chain ID, safe head, historical code, and log queries, then point `kernel_canary_reconciler_secondary_rpc_url_ssm_parameter_name` at that parameter. The override applies only to the isolated Kernel reconciler.

Check the dark API task from an approved in-VPC probe. After the private qualification passes, set `kernel_canary_managed_alto_qualified=true` and `kernel_canary_managed_alto_qualified_image` to the full ECR URI with the tested digest. A changed Alto image requires fresh evidence before route or payment activation. For the bounded wallet test, set an exact HTTPS `kernel_canary_preview_origin` outside `plether.com` and its subdomains and set `kernel_canary_route_enabled=true`. The listener rule uses priority 180 and matches host `api.sepolia.plether.com` and backend path `/api/aa/kernel/rpc`. The dedicated Pages preview Worker maps browser `/api/perps/v1/aa/kernel/rpc` to that path with its origin token. Both payment modes require the exact external and Privy owner addresses in `kernel_canary_owners_json` and keep public admission false. Sponsored mode additionally requires the new Core paymaster profile and active canary reconciler.

To roll back, set `kernel_canary_route_enabled=false` and both payment flags to false. This closes ingress and removes the API task role's paymaster KMS signing grant. Scale the canary API and Alto to zero. Keep the reconciler at `kernel_canary_reconciler_desired_count=1` with its attested Kernel and paymaster profiles until accepted operations and sponsorship reservations settle or expire. Then scale the reconciler to zero. Retain the additive database schema and signing keys for durable evidence and old-binary compatibility.
